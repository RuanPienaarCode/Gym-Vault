A ## heading with no weekday in brackets still folds into the day above it. Nothing in the plan library is shaped that way, and a parser that guessed would have to decide between "this is a new day" and "this is a note about the current one" with no way to ask. Guessing wrong would corrupt a user's own file more quietly than the current behaviour does. The reasoning now sits in a comment at that exact line, along with the note that a load-time warning, not a parse-rule change, is the safer shape if it is ever revisited.

Recurring pattern: two rules for one figure

Five findings share a root shape the author's other repos know well. The same value is derived by different rules on different screens, and the screens disagree.

  • H3 reps mode trusts the exercise unit, timed mode trusts the written unit.
  • H6 the reps screen saves an untouched weight prefill, the timed screen clears it.
  • M1 the row writer saves interval seconds for rep entries, the records reader treats every seconds as a hold.
  • M2 the timed clock equals the plan target, yet is marked measured.
  • L7 the completion tile floors elapsed minutes at 0, the note floors at 1.

They were fixed as one change, not four. The boolean "measured" flag became opts.observed, a list of the kinds a screen actually watched, and a new exported claimableKinds decides from an exercise's own unit which kinds it may ever claim. Both screens now pass through the same seam, and the records page and the goals page read the same rule.

Decisions taken

Five findings turned on a product call rather than a defect. Each was taken with the default below and built that way. Say the word on any of them and it changes.

  1. Any-day plans fill empty weekdays, in the app. The alternative was re-flagging ten plans in the separate library repo. The app fix was chosen because those plans already promise this in their own prose, and it also covers any future plan shaped the same way without a second repo needing a push.
  2. Make active is hidden for parallel and fallback plans. They now state what they do instead. A switch that cannot work is worse than no switch.
  3. An untouched weight prefill is still saved, but never claims a record. Tick-to-accept stays, because doing the prescribed weight is real information. Celebrating a number nobody measured is not.
  4. Interval time on a rep exercise is excluded from records and duration goals. It is still written to the row, because the clock genuinely knew it. It just no longer counts as a hold you never did.
  5. Done at zero reps still saves a zero row. Left deliberately alone: a failed set is real data. Only the all-blank run row, which carries no information at all, is now dropped.

Coverage gaps

The guard suite is green at 55 files and renders no pages. Every session-screen guard is a regex on source, so nothing below is executed by a test today.

  • Motion subscription lifecycle across renders (H5); draft survival across navigation (H4).
  • Record claims on the reps screen for weight (H6); Records and goals reading seconds off rep exercises (M1); a duration interval equal to its target (M2).
  • Log-page structural edits against a live timed schedule (M3); completion-screen exits with zero rows (M4).
  • Make-active scoping (H1); the day resolver with an any-only active plan (H2); duration inference in makeEntry (H3); day resolution by name versus index (M5).

  • The library at ~/Github/gym_plans is never parsed by the plugin's own parser in CI, though all 27 plans round-trip today with zero lines rewritten.

What the browser harness cannot reach

  • Start on the setup page into a live session: the setup harness has no controller behind it.
  • Finish & save writing a workout note: the counter harness never stubs the save. The plugin's own error handling caught the missing function cleanly, which is a good sign.
  • Timed-mode circuits, motion counting, voice, run records and sound cues were not driven this pass; each has its own harness page.
  • Anything animation-gated: the pane stayed hidden, so requestAnimationFrame never ticked.

Method

Three lanes ran in parallel against ~/Github/gym-vault at commit 8469070, version 0.11.2, whose main.js, styles.css and manifest.json are byte-identical to the vault's installed copy.

  • Plan-side static trace over exercises, plans, edit, delete, select, mode storage and file persistence, with node reproductions against the real modules and all 27 files of the plans library.
  • Session-side static trace from setup through counter, rest, completion and the readers of the written data, with node reproductions and a timer audit (every interval, timeout and animation frame is cleared except the motion listener in H5).
  • Browser click-through of the preview harness at 390px and 1280px: setup, counter, target meter and nav pages, driven by dispatched DOM events with the console read after each step.

Consolidation: 31 raw findings, one duplicate (both lanes flagged the setup page's Back at the same lines, merged as M7). Severity follows the owning lane. Every High was opened at the cited line by the main thread before inclusion; H5 stays High but is marked suspected because it needs a motion sensor to reproduce.

The fix pass

Five lanes then worked disjoint sets of source files on branch fix/journey-audit-0.11.2, so no two ever held the same file. Every behaviour change carries a guard test, and every guard was run against the unfixed code first and required to fail by name before the fix went in. That rule caught real weakness: this repo has previously shipped guards that passed against the very bug they were written for.

Two rules that were only testable by writing a second copy of them, the day resolver and the draft description, were lifted out of the controller closure and exported, so their guards now execute the shipping code rather than a model of it. The Today screen's new slabs are proven by rendering the real page against a DOM stub, not by matching source.

A browser pass then drove every reachable fix on the rebuilt harness at phone and desktop width, in both light and dark: the empty-day Start gate, the shared Back, the completion-screen exit, the all-skipped Discard, the weighted prefill saving without claiming a record, and the timed prefill dimming. Two harness pages were themselves broken and were repaired, since the harness is the verification tool: the setup page threw before rendering because its stub predated the shared back button, and the count-in page called a function that has never existed in this codebase.

The build is green at 73 test files and the bundle compiles. The plugin has NOT been deployed to the vault and nothing has been committed or pushed.
