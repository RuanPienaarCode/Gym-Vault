shipped 0.7.0T2Start button hidden behind Obsidian's floating navbarSmallRoot cause found

Root cause

This is already solved once, in the wrong place. src/styles.css:1483 carries the correct rule — body.is-phone .gv-app .gv-session-page { padding-bottom: calc(var(--view-bottom-spacing, …) + 12px) } — because Obsidian mobile's navbar is position: fixed and overlaps view content instead of reserving space. But the session setup screen renders into .gv-page, which only has padding-bottom: calc(32px + env(safe-area-inset-bottom)) (line 297). The safe-area inset does not account for the navbar, so the Start button lands underneath it.

Change

Extend the --view-bottom-spacing rule to cover .gv-page, not just .gv-session-page — one declaration, both surfaces. Every page with a bottom action benefits, not only setup.

Trap

Do not hard-code 52 px. The host computes the exact clearance in --view-bottom-spacing and it is 0 when the navbar is not floating; the existing rule's fallback chain already handles a host without the variable. Copy that chain, do not invent a second one.

Done when

tests/css-guards.test.cjs asserts .gv-page is covered by the navbar-clearance rule, and Start is fully tappable on your iPhone at the bottom of a long setup screen.

Phase 1 · The counter

Six tickets that together turn the counter from "a number that goes up" into a set with a beginning, a target and an end. T3 must land before T4; T7 must land before T6.

shipped 0.8.0T3Set the target before the counter appearsMediumBlocks T4

What exists

Most of the parsing is already written. src/plan-parse.js gives targetFirstNumber() and targetIsDuration(), and src/page-log.js makeEntry already turns a plan line like 4 x 12 into a prefilled reps. startDraft already accepts opts.setsPerEntry to override the plan's set count — the timed mode uses it today. The freestyle counter has no notion of a target at all.

Change — both surfaces, as you chose

  • New pure module src/counter-target.js: one function that resolves a target to {kind: 'reps'|'seconds', value} or null, from either a plan target string (reusing plan-parse, never re-parsing) or an explicit user entry. Unit-tested with no DOM.
  • Freestyle (src/rep-counter-modal.js): a first step before the tap zone — reps or time, quick chips (8 · 10 · 12 · 15 · 20, 30s · 45s · 60s), a free entry, and an explicit open-ended choice.
  • Guided (src/page-session-setup.js): a per-exercise sets/target override, written through the existing setsPerEntry path rather than a second mechanism.

Trap

A target is a prefill, not a result. The codebase draws a hard line between a prefilled figure and a measured one — see set.touched, and applyCompletion's measured flag, which exists precisely so a timed circuit never claims a record for a number nobody watched you produce. A user-entered target must not mark a set touched and must never become a logged figure on its own.

Done when

Opening the freestyle counter asks what you are going for, and answering it (or skipping it) reaches the same tap zone that exists today with the target carried alongside.

shipped 0.8.0T4Power-up / flame fill toward the targetMediumBlocked by T3

Change

The tap zone gains an energy fill that rises with each rep or each second of a hold, floods at 100 %, and escalates visibly at the last few. Drive it from one CSS custom property (--gv-fill: 0..1) set on the zone in showRep(), with the animation entirely in src/styles.css — compositor-driven transitions, no per-frame JS loop.

Traps

  • No target, no bar. Open-ended sets keep today's flash. A progress bar with no destination is a lie.
  • Reduced motion. confetti.prefersReducedMotion() already exists and is already honoured by the media cycle — reuse it. Under it, the fill steps without animating.
  • Overshoot. Reps past the target are a good thing, not an error state. Decide what 130 % looks like before building 100 %.
  • iOS 15 floor. Anything needing a newer CSS feature needs an @supports guard, and per your own notes those guards do not silence the community review linter — so prefer features that were already safe at the floor.

Done when

A 12-rep target fills visibly and unmistakably across 12 taps on your phone, at 60 fps, with the screen awake, and does nothing distracting under reduced-motion.

shipped 0.7.0T5Enter reps manuallySmall

Change

A "Type it" button in the control bar (.gv-rc-bar) opening a numeric entry that sets the count directly. Wire it once in src/rep-counter-shared.js so the freestyle modal and the guided counter get the same button and the same rules — that module exists for exactly this reason.

Trap

A typed count is user-typed, which the record logic already treats as trustworthy via typedByUser. Setting the count must therefore also mark the set touched, or you get a figure that saves but is never eligible for a record — one of the "two figures derived by different rules" bugs this repo keeps producing.

Done when

Typing 15 mid-set and pressing Done logs 15, and beating a previous best of 12 that way celebrates exactly as a tapped 15 would.

shipped 0.7.0T63 · 2 · 1 · Begin before a set startsSmallBlocked by T7

What exists

Timed circuits already count down between intervals — countdownRing() in src/page-session.js:774, with spoken 3-2-1 already wired at src/page-session-setup.js:336. There is already a countdown in this app.

shipped 0.7.0T7Voice, beeps, buzz or silentMediumBlocks T6

Change

New settings soundMode: 'voice' | 'beep' | 'vibrate' | 'silent' and voiceURI, added as flat keys to DEFAULT_SETTINGS in src/constants.js — that file's own comment explains why nested objects break the shallow settings merge.

New façade src/sound.js with two entry points — announce(n) for a rep or a hold checkpoint, cue(kind) for begin / record / goal. Every existing speak() caller moves behind it: src/rep-counter-shared.js, src/page-session.js (reps, holds, timed intervals, celebrate), src/rep-counter-modal.js.

Platform truths to design around

  • Voices load late. speechSynthesis.getVoices() returns an empty array on first call in several engines; the settings picker must listen for voiceschanged and re-populate, not render an empty dropdown once.
  • Voices are device-specific. A voice chosen on your iPhone will not exist on your Mac. Store the URI, fall back to the default when it is missing, and say so in the settings copy rather than silently going quiet.
  • Beeps ship as code, not files. Synthesise with WebAudio — a short oscillator burst. No audio assets in the bundle keeps the plugin small and the community review clean.
  • Vibration is Android-only in practice. iOS WebKit does not implement navigator.vibrate. Offer the option only where the API exists, rather than shipping a setting that does nothing on your own phone.

Trap

The existing per-session mute button is not this setting. Mute means "silence right now"; the setting means "this is how I want to be told". Keep both, and keep the screen-reader aria-live checkpoints ungated by either — the comment in durationBody already explains why.

Done when

Each of the four modes is audibly (or palpably, or not) different on your phone, and nothing crashes on a device where the chosen voice is absent.

Phase 2 · Records

You asked for all three: a post-session screen, a dedicated page, and per-exercise history. All three read from one new data layer — that is T9, and it blocks the other two.

shipped 0.8.0T9Records data layerMediumBlocks T10, T11

What exists

src/records.js answers one question — did this set beat the previous best — and deliberately delegates the maxima to stats.exerciseBests. Its header says why: two figures derived by different rules is this codebase's recurring bug shape.

Change

Two new pure functions in the same module, both built on exerciseBests's rules and nothing else:

  • recordHistory(workouts, exercise, kind) — the ascending sequence of every time the best was beaten, each with the date and the figure. This is what the exercise page shows.
  • allRecords(workouts, exercises) — current best per exercise per kind, with the date it was set. This is what the Records page shows.

Trap

The temptation is a faster bespoke scan that walks the rows once. Resist it. If allRecords and exerciseBests can disagree on a single exercise, the Records page and the exercise page will show two different numbers and you will spend an evening finding out why.

Done when

tests/records.test.cjs proves, on seeded data, that every figure allRecords reports is identical to what exerciseBests reports for the same exercise.

What exists

applyCompletion increments sess.recordCount and throws away the detail; renderComplete then prints "2 records broken". The margin you want is computed and discarded.

Change

shipped 0.8.0T13Exercise frame audit — how many really have all their phases?Investigate first

What exists

Frames come from each exercise note's image: frontmatter, resolved by resolveExerciseImages in src/page-exercise-detail.js:123. The guided view already supports up to four frames (MEDIA_MAX_FRAMES = 4), so the plugin is not the limit.

The thing to know before promising a fix

The upstream source only has two frames

Nearly every image is a free-exercise-db URL, and that database ships exactly 0.jpg and 1.jpg per exercise — the code even derives the second from the first for older notes. So "box jumps is missing the landing frame" may not be a missing link; there may be no third frame to link to. If that is what the audit finds, the fix is not an edit — it is sourcing images, which is a different and much larger decision.

Change

A script — scripts/audit-frames.mjs — that walks the seeded exercise notes and the gym_plans library and reports, per exercise: how many image: entries, how many actually resolve, and whether the movement name implies a phase the pair cannot show (jump, box, burpee, clean, snatch, get-up, turkish, thruster). Output is a table, not an edit.

What it found

node scripts/audit-frames.mjs, over the 66 seeded exercises:

  • 19 have no image at all — Burpees, Wall Sit, Hollow Hold, Dead Hang, Side Plank, Pike Push-ups, Bulgarian Split Squat, Hanging Knee Raise and eleven more. This is the real finding, and it is a bigger one than the question asked.
  • 46 have the classic start/finish pair. One (Pull-ups) has three.
  • 7 look multi-phase with two frames or fewer — Box Jumps, Muscle-ups, Box Step-ups, Kettlebell Swing, Kettlebell Thruster, Turkish Get-Up, Burpees.
The decision this hands back

Neither number is fixable by editing a link. free-exercise-db has no third frame to point at, and it has nothing at all for the 19 — those are bodyweight holds and unilateral movements it simply does not cover. So the question is not "which links are broken" but "are we sourcing images", which is a project. The plugin side needs no change: it already renders up to four frames.

The script itself over-counted on its first run — it swept up goals and running entries and reported 29 missing. Scoped to SEED_EXERCISES, the real number is 19.

Phase 4 · Running

T14Run recorder: timer, distance, speed, elevationLargePlatform risk

You chose to build the full GPS recorder rather than spike it first. Noted and proceeding — but the risk is real enough to be the ticket's first hour rather than a footnote.

Step one, before any UI

A ~30-minute probe on your actual iPhone: does navigator.geolocation.watchPosition fire inside Obsidian iOS? Does it prompt for permission? Does it keep firing with the screen locked, or only in the foreground? Is the app:// origin a secure context as far as WebKit is concerned? Every line of the recorder rests on those four answers. If any is "no", the ticket delivers the manual recorder below and reports back — nothing is wasted either way.

Structure

  • src/geo-track.js — pure, no DOM, no geolocation import: takes position fixes in, gives distance, pace and elevation gain out. This is where the actual correctness lives and it is unit-testable with recorded fixture fixes.
  • src/page-run-recorder.js — start / pause / stop, live km, pace and elevation, holding the screen awake via the existing holdWakeLock(). On stop it writes one workout row through the same path the log page uses.
  • Run page (src/page-running.js) gains the entry point.

The hard part is not the timer, it is the noise

  • Drop fixes with poor accuracy (a 100 m fix under trees will add phantom kilometres if you integrate it).
  • Drop physically implausible jumps between consecutive fixes.
  • Elevation is the worst of them. Consumer GPS altitude is noisy enough that naïve summing invents 200 m of climb on a flat road. Ignore altitude entirely when altitudeAccuracy is null or poor, and apply a minimum-change threshold before counting a metre of gain. Whatever rule you pick, write it down in the module header — a plausible-but-wrong elevation figure is worse than no figure.
  • Pace from the accumulated distance and the clock, never from the per-fix speed field, which is unreliable and would give you two figures derived by different rules.

Storage

The summary (distance, seconds) fits the existing WORKOUT_COLUMNS, which already has distance_km. The track — the polyline — does not belong in a markdown table. Open decision below.

Privacy

Location data never leaves the device and is never sent anywhere; it is written into the user's own vault. Say that in the permission prompt copy and in the README, plainly. This plugin is public and in the community store — a location feature with no stated privacy posture is the kind of thing directory review asks about.

Done when

A real run on your phone produces a distance within a few percent of a known route, a pace that matches your watch, and an elevation figure you would be willing to defend — or a written finding that geolocation does not work in this host, and a manual recorder that does.

RegressionT15The Start button is still under the floating navbar

What happened

T2 shipped in 0.7.0 as a fix for exactly this, and a photo of the session-setup screen on an iPhone still shows Start session sitting under Obsidian's navbar pill. So either the fix is insufficient or it is not applying — it was verified by computing the CSS in a desktop browser, which is not the same as looking at the phone, and that gap is the lesson here.

What is known

  • The rule now lives on .gv-page, the scroll container, floored at the old 32 px so nothing lost padding. Four branches were confirmed to compute correctly: 32 px on desktop, 64 px with no host variable, 95 px with a floating navbar, 32 px when the navbar is not floating.
  • The Start button is .gv-hero-action, which bleeds sideways (margin: 18px -17px 0) but is an ordinary last child vertically — so container padding should push it clear.

The three things to check on the device, in order

  1. Is the vault running 0.7.0? A green build installs nothing; compare the sha256 of the vault's main.js against the release asset, and reload Obsidian.
  2. Does body carry is-phone? The rule is keyed on it. If the host uses a different class on this build, the rule never applies.
  3. What does --view-bottom-spacing actually resolve to there? If the host reports 0 while the navbar IS floating, the floor gives 32 px against a ~52 px navbar and the fix is simply too small — in which case the floor becomes the navbar height rather than the old padding.

Possible fourth answer: the screen was not scrolled to the bottom and there is more below. Worth eliminating first, since it costs nothing.

Featureshipped 0.8.0T16Edit a plan: change the reps, reorder the exercises

What exists

The plan detail page can add a day, add an exercise line, and remove one (the ✕ per row). It cannot change 1 × 15 to 1 × 20, and it cannot move an exercise up or down — for either you open the note and edit the markdown by hand.

Change

  • An Edit toggle on the plan detail page that turns each row into an editable prescription (sets × target, and the optional @ Nkg) plus up/down controls.
  • Everything round-trips through src/plan-parse.js, which already owns both directions — parsePrescription reads 5 x submax and the serializer writes it back. Nothing here should hand-build a markdown line.

Traps

  • The note is the source of truth, and it holds hand-written coaching prose. The existing add/remove path was built specifically so that survives a save; a reorder that rewrites the day's table must go through the same path or it will eat someone's cues.
  • Plans, goals and logged rows all reference an exercise BY NAME. Reordering is safe; renaming is not, and this ticket must not grow a rename field by accident.
  • Drag-to-reorder is the obvious design and the wrong one here. This screen lives inside a scrolling Obsidian pane on a phone; up/down buttons are unambiguous, reachable by keyboard, and cannot fight the scroll container.

Standing rules this plan obeys

  • Green tests prove nothing about the UI. This suite renders no pages. Every ticket ends with a runtime check in your vault on your phone, not with a passing npm test.
  • A green build installs nothing. Artifacts have to land in <vault>/.obsidian/plugins/gym-app/ and be proven byte-identical before "it works" means anything — that is the dev-loop runbook, every time.
  • iOS 15 WebKit is the floor, not minAppVersion. No lookbehind regex, no Node APIs in src/, no innerHTML.
  • One rule, one place. Two figures derived by different rules is this repo's recurring bug shape. It is why T6 extracts the existing countdown instead of writing a second one, why T9 builds on exerciseBests, and why T10 extends describeRecord.
  • Releases: Phase 0+1 → v0.7.0, Phase 2+3 → v0.8.0, Phase 4 → v0.9.0. Three files bump, tag carries no v prefix, CI byte-compares the artifacts.
